# Профілі LeCook

Neon Managed Auth з email/паролем. `NEON_AUTH_BASE_URL` задає гілку авторизації.
Дозволений origin `https://lecook-api.onrender.com`; для іншого розгортання —
`LECOOK_AUTH_ORIGIN` і відповідний allowlist у Neon. Не використовуйте URL тестової
гілки в production. Власний auth-сервер і зберігання паролів не реалізуються.

Маршрути `/api/account`:

- `POST /auth/signup`, `/auth/login`: email, password, name → непрозора сесія та користувач.
- `GET /auth/session`, `POST /auth/logout`: перевірка та відкликання сесії.
- `GET /book`: `{revision, book: {recipes, favorites, preferences}}`.
- `PUT /book`: той самий формат; 409, якщо revision застаріла.
- `POST /photos` (image/jpeg), `GET /photos/{hash}`: приватні фото власника.
- `POST /publish/{local UUID}`: явна публікація незмінної копії до каталогу.

Клієнт використовує `Authorization: Bearer <opaque session>`. Це підписане
значення cookie, отримане через документований REST API Managed Auth, не
JWT і не адміністративний ключ. Кожен приватний запит перевіряється через
Managed Auth `/get-session`; ID власника береться лише з відповіді провайдера.
Після виходу сесія відкликається. Android шифрує її ключем Android Keystore
і зберігає шифротекст у noBackupFilesDir. Пароль не зберігається.

Flyway V3 додає приватні книги, приватні фото, зв’язок публікацій та поля БЖВ.
Книги перевіряються перед записом; максимум 500 рецептів / 4 МБ JSON,
10 000 вподобань. Фото — JPEG до 1 МБ / 2048 px, максимум 100 на профіль.
Для цього прототипу приватні фото зберігаються в PostgreSQL BYTEA: наявний
public_read bucket не використовується для приватних чернеток. При публікації
лише вибране фото копіюється до публічного object storage. Масштабування фото
потребуватиме приватного bucket і обліку зайнятого місця.

Публікація зберігає М–М склад, кількості, кроки, час, порції та авторські КБЖВ.
Повтор запиту не створює другу публікацію. Редагування приватного оригіналу не
змінює вже опубліковану копію. Обмеження прототипу: до 100 публікацій на профіль;
модерація, відновлення пароля та підтвердження email в інтерфейсі ще не реалізовані.

Android розділяє локальні дані за власником, зберігає несинхронізовані зміни
й версію книги між перезапусками. При 409 автоматичний запис зупиняється.
Явне об’єднання залишає різні версії рецепта окремими копіями, поєднує вподобання
і зберігає харчові вподобання поточного пристрою. Гостьова книга переноситься
в профіль лише окремою дією з підтвердженням.

Перевірка на окремій Neon-гілці: реєстрація двох користувачів, повторний вхід,
відновлення книги/вподобань/фото, 401 без сесії, 404 для чужого фото, 409 при
застарілій версії, одноразова структурована публікація та відкликання сесії.
